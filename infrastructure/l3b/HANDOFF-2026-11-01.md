## Setup chronology and decisions

The sequence below records completed actions and superseded choices without inventing exact timestamps for each step.

1. Connected as root to the new Debian node at its original DHCP address `10.1.1.245`. Established OS, kernel, interface, routing, root filesystem and hardware state.
2. Selected official Debian Backports for the newer Debian-packaged kernel. Installed and booted `7.2.11`, verified network/storage/security, then removed the old 6.12 images.
3. Assigned `10.1.1.10/24` directly to `eno1` using existing ifupdown; retained the existing gateway and set the requested public resolvers. Verified new SSH access before dropping the old address.
4. Removed the original `av` account. Created `dev` and, initially, a separate `l3b` account with public-key login, sudo and KVM permissions. Later removed the `l3b` account completely at the owner's request; final administrators are root and dev.
5. Applied the reviewed minimal key-only SSH configuration, created persistent swap, set the CPU/THP policy and small targeted sysctl changes. Verified KVM access without deploying a VM.
6. Powered the node down on request for physical upgrades. The owner added memory and replaced the first SATA SSD. The node subsequently returned online with nominal 32 GB RAM and the replacement SSD.
7. Examined both SATA SSDs using SMART and standardized ATA statistics. Distinguished estimated endurance from general reliability and documented historical errors rather than reporting a single absolute health percentage.
8. Hid the normal GRUB menu at the owner's request. Built a compact colored ASCII login table, then revised units, CPU percentage and conditional failed-unit reporting.
9. Corrected local host naming to `l3b.cc.cd`, removing the unwanted repeated `l3b.l3b.cc.cd` name.
10. Reviewed drivers and firmware. Retained BIOS 1.31.0 per the owner's stability experience. Updated the replacement Seagate SSD from ST200354 to ST200355 using the official vendor tool/firmware and verified the result. Researched the Samsung OEM NVMe update but did not flash an unsupported package.
11. Partitioned/formatted the approved replacement SATA disk and finalized its UUID mount at `/data`. An initial `/srv` choice was superseded; `/srv` is not the data disk mount.
12. Installed Docker using the requested official convenience script. Kept Docker state on the root disk, disabled Docker's default bridge, enabled a custom shared bridge, and tested container DNS, cross-stack connectivity, outbound traffic and bind-mount persistence.
13. Installed shared development runtimes and build tools. Kept user-installed npm tools writable under dev's home and the shared toolchains administrator-managed.
14. Installed Herdr globally, OpenCode V2 and its Herdr integration, and native Claude Code for the official Claude Agent login path.
15. Installed 1Password CLI and GitHub CLI for dev only. Copied the explicitly authorized Mac SSH identity directly to dev without displaying either key. Configured Git identity and verified GitHub SSH authentication.
16. Temporarily mounted the existing HOMELAB_BACKUP ext4 filesystem without modifying its partitioning or adding persistence.
17. Repaired OpenCode self-upgrade handling by using a dev-owned installer-style binary location and a persistent Bash function selecting `--method curl`.
18. Installed the official Notion CLI for dev only, configured the owner-selected protected local credential backend, repaired its required config schema field, completed browser authentication and verified all seven native doctor checks.
19. Prepared this dated handoff from the session record and live audit. Documentation work does not itself restore the retired cluster or deploy application stacks.

### Applied performance policy

`/etc/sysctl.d/90-homelab.conf`:

```text
vm.swappiness = 10
vm.dirty_background_bytes = 67108864
vm.dirty_bytes = 268435456
fs.inotify.max_user_watches = 524288
fs.inotify.max_user_instances = 1024
net.ipv4.ip_forward = 1
```

Swappiness makes swap less eager; it does not disable swap or prevent OOM. Fixed dirty thresholds bound buffered-write accumulation. Higher inotify limits accommodate many repositories/watchers. IPv4 forwarding was added for the custom Docker bridge because disabling Docker's default bridge did not automatically enable forwarding in this setup.

`/etc/systemd/system/homelab-performance.service`, enabled and active:

```ini
[Unit]
Description=Homelab CPU and memory policy
After=systemd-sysctl.service

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStart=/usr/bin/python3 -c "from pathlib import Path; [p.write_text('performance') for p in Path('/sys/devices/system/cpu/cpufreq').glob('policy*/scaling_governor')]; Path('/sys/kernel/mm/transparent_hugepage/enabled').write_text('madvise')"

[Install]
WantedBy=multi-user.target
```

All six CPU policies report `performance`; Intel pstate and boost remain available. THP is `madvise`, so suitable applications can opt in. Existing THP defrag madvise behavior was retained. The policy survived subsequent reboots. The performance governor may increase power consumption/heat; no workload benchmark established a throughput improvement.

Root XFS uses `noatime`. NVMe scheduler `none`, existing fq_codel/Cubic networking, MTU 1500 and 1 GbE link behavior were retained rather than applying broad unmeasured tuning. `fstrim.timer` remains enabled. No fixed hugepage reservation, CPU isolation or speculative VM tuning was introduced.

### Shared network

Final user-defined bridge name **`l3b`**, subnet `172.17.0.0/16`, gateway `172.17.0.1`. The initially created `homelab` name was replaced while empty. Final networks are `l3b`, `host`, `none`; the default `bridge` / docker0 network is disabled. Docker's firewall/NAT handling was retained and host IPv4 forwarding enabled. Disabling the default bridge does not mean disabling all bridge networking.

Docker has no daemon switch making an arbitrary custom bridge the implicit default for every standalone container. Explicitly select it:

```bash
docker run --network l3b IMAGE
```

For each Compose project, declare the existing shared network as its default:

```yaml
networks:
  default:
    external: true
    name: l3b
```

Services on that bridge can resolve each other through container/service aliases without fixed IP configuration. Use unique service aliases across stacks to avoid ambiguous duplicate names. This shared network provides broad cross-stack reachability; it does not isolate stacks from one another. Publishing a port is needed for host/LAN access, not for ordinary communication between containers on this network.

Validation during setup included dev Docker access without sudo, container DNS and HTTP communication, external DNS/HTTP egress, two separate Compose projects communicating through a shared service alias, and host bind-mount data visible in a replacement container. Temporary projects, containers, test image and bind-test directory were removed. No actual application stack was deployed as part of these tests.

## Login information table

Custom script: `/etc/update-motd.d/10-homelab`. Static `/etc/motd` is empty; the stock 10-uname executable was disabled. Existing Debian PAM dynamic MOTD handling is retained with SSH `PrintMotd no`, avoiding duplicate banners. `/run/motd.dynamic` is generated runtime output.

The final design uses ASCII borders, a 36-character visible width, compact labels and wrapped values, with ANSI gray borders, cyan labels and yellow warnings. Healthy output has Host, OS, Kernel, IP, Uptime, CPU, RAM, Swap and Disk `/` rows. Values use decimal **GB**, per the owner's request, rather than labeling GiB as GB.

CPU is an approximately one-second `/proc/stat` delta across all CPU cores, expressed as overall busy percentage. Idle and iowait are excluded from busy time and guest counters are not double-counted. It is a login-time sample, **not** a historical utilization average or the Unix load average; the sample adds about one second to interactive login. RAM uses total minus MemAvailable, and storage comes from statvfs. Disk `/` is the root filesystem, not a claim that every mount is displayed.

The `Status OK` row was removed. Status appears only if systemd reports failed units, with their count; if the query fails it can report that the check is unavailable. Healthy and simulated-failure layouts were checked after stripping ANSI escapes, with each visible line at the intended width. Fresh interactive SSH rendered the table; noninteractive SSH command output remained suitable for agents.
