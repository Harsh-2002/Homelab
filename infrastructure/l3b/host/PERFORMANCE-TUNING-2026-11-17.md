# l3b performance tuning, 17 November 2026

Owner-approved, measured, and applied live. The host is one Debian 13 node (Dell
OptiPlex, i5-9400T, 6 cores, 31 GiB RAM, Intel e1000e 1 Gbps, kernel 7.2.11).

## Baseline (measured before any change)

| Area | Finding |
|---|---|
| CPU/disk | Governor `performance`, THP `madvise`, NVMe scheduler `none`, SATA `mq-deadline`. Already correct. |
| Memory | `swappiness=10`, dirty bytes capped (64 MiB / 256 MiB), `max_map_count` 1,048,576, 524,288 open files. Already correct. |
| Swap | 8 GiB `/swapfile` on the NVMe root (XFS) was full, but swap I/O was only ~2 KB/s in and ~5 KB/s out. Memory pressure (PSI) was 0.00. The swapfile held idle pages. |
| NIC | e1000e, 1 Gbps full duplex, MTU 1500, 0 CRC/frame/FIFO errors. 0.04% rx drops. |
| UDP | 1,569 `UdpRcvbufErrors` over 8 days (default socket buffer 212 KB). |
| I/O pressure | PSI `io full` about 2-3%. Not caused by swap and not attributed to any single process in a 10-second sample. Not resolved by these changes. |
| OOM | Two kernel OOM kills on 16 Nov 10:18 and 10:28. Victim: Orva test process `commands.test` at 22-25 GiB RSS, a child of `opencode.service`. OpenCode itself used about 0.8 GiB. |

## Applied

### `/etc/sysctl.d/91-homelab-network.conf`

| Setting | Before | After | Reason |
|---|---|---|---|
| `net.ipv4.tcp_slow_start_after_idle` | 1 | 0 | Caddy holds long-lived HTTP/2 connections; keeps the congestion window across idle gaps. |
| `net.core.rmem_default` | 212992 | 1048576 | Removes UDP receive-buffer overflows. `rmem_max` is already 4 MiB. |
| `net.core.wmem_default` | 212992 | 1048576 | Same, send side. |
| `net.core.netdev_max_backlog` | 1000 | 5000 | Larger queue before drops under bursts. |
| `net.ipv4.tcp_max_syn_backlog` | 2048 | 4096 | Matches `somaxconn` (4096). |

### zram swap

`systemd-zram-generator` 1.2.1 with `/etc/systemd/zram-generator.conf`:
`zram-size = ram / 4` (7.79 GiB virtual), `zram-resident-limit = ram / 8` (3.89 GiB of
real RAM at most), `zstd`, `swap-priority = 100`. The existing `/swapfile`
(priority -1) stays as overflow. `/etc/sysctl.d/92-homelab-zram.conf` sets
`vm.page-cluster = 0` (no swap readahead; there is no seek cost in RAM).
`swappiness` stays 10.

Existing pages already in the swapfile are not moved to zram; they migrate only
when touched. This is deliberate: draining the 8 GiB swapfile needs 8 GiB free RAM.

## Verification (all on the live node, 17 Nov 2026)

- `sysctl --system` applied 90, 91 and 92 in order with no errors; every live value
  matches its file. `systemd-sysctl --cat-config` lists them, so they persist.
- `/proc/swaps`: `/dev/zram0` priority 100, `/swapfile` priority -1. zram resident
  limit reads 3.89 GiB. `dev-zram0.swap` is generated by the generator at boot.
- Functional test in a memory-limited scope (`MemoryMax=450M`): 1 GiB written, 729 MiB
  swapped into zram using 8 MiB of RAM, the swapfile grew by only 0.9 MB, and 0
  integrity errors after swap-in. The ratio (156x) is inflated by mostly-zero test
  data; expect 2-3x on real pages. zram returned to 0 afterwards.
- Health after change: `systemctl is-system-running` = running, 0 failed units,
  39 healthy containers and none unhealthy, `notes` and `oc` return 200, SMB 445
  open, WireGuard listening.
- Not tested: an actual reboot (the generated swap unit and sysctl files were
  validated instead), and a before/after network throughput benchmark.

## Honest expectation

On a 1 Gbps LAN with about 20 established connections, the network changes are
small and may not be measurable. zram adds burst headroom; it did not reduce I/O
pressure because swap I/O was not the source.

## Deliberately not changed

- BBR, jumbo frames, CPU governor, disk schedulers, NIC offloads, dirty and cache
  settings: already right or no measured gain.
- `opencode.service` memory limits and sandboxing of heavy tests: the owner
  declined these for now. The 16 Nov OOM kills are therefore **not** prevented. The
  leftover microsandbox `iam-artifact-owner-test` (4.1 GiB) was not touched.

## Rollback

```
sudo systemctl stop dev-zram0.swap
sudo apt-get remove systemd-zram-generator
sudo rm /etc/systemd/zram-generator.conf /etc/sysctl.d/91-homelab-network.conf /etc/sysctl.d/92-homelab-zram.conf
sudo sysctl --system
```

Pre-change values are the "Before" column in the table above (the backup file was deleted on 2026-11-18).
