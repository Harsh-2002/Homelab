## Query statistics: actual recurrence mechanism found by HA testing

After promotion pg_stat_statements disappeared again. The initial image seed and
the repair had created it, but CNPG's managed-extension logic removes its SQL
objects unless a pg_stat_statements.* parameter enables management. Merely listing
the shared preload library was insufficient. This explains recurrence during
reconciliation/promotion; it supersedes the earlier unproven omission explanation.

The Cluster now declares pg_stat_statements.track:top. CNPG recreated the extension
in public; migration v5 moves this relocatable extension into extensions without
dropping/recreating it. Tests accept either supported search-path location rather
than treating schema placement as a missing extension. The static init-contract
guard requires the managed parameter. Existing completed Job templates were not
mutated: the new versioned Job is supabase-observability-init-v5.
