# Jellyfin playback failed after a successful ARR import

## Symptoms and evidence

The Drama had reached 100% in qBittorrent and Radarr had imported it. Jellyfin listed the movie, but the browser reported a fatal player error. Merely checking the library API and poster page had missed the failure.

The server logged `ffprobe failed - streams and format are both null` and FFmpeg exit 234 with `Error opening input: Invalid argument`. A plain `head` of the library file on both `ctr` and inside Jellyfin also failed with `EINVAL`, proving the failure occurred before media decoding. Intel's render device and driver initialized correctly.

On Store, both download and library paths were readable Matroska files. They were hardlinks to inode 7077894, size 6,433,506,312 bytes, link count 2. On the existing CIFS mount, reading the original download worked while opening the library alias failed. A separate read-only SMB connection read the library alias successfully. A connection mounted with `nolease` read both aliases.

This matches the documented Linux CIFS lease-key conflict when different applications open different hardlink names for the same inode. The evidence isolates the client mount/lease behavior; this incident did not establish a particular kernel commit as the regression source.

## Applied fix

Added `nolease` to the tracked `infrastructure/ctr/mnt-AV.mount` and the live systemd unit. Stopped the six AV-consuming containers through the Portainer Docker API, reloaded systemd, restarted the mount, verified SMB3 encryption and `nolease`, then started the same containers. No media was deleted, copied or re-downloaded. No whole-host restart or kernel change was needed.

The option disables SMB lease/oplock caching for this mount. It can reduce cache performance, but preserves hardlink space savings and was adequate for tested playback. Other SMB clients and the BACKUP/ISO mounts were not changed.

Refreshed the movie's previously failed Jellyfin probe metadata. FFprobe then recognized 1920×1040 HEVC video, E-AC-3/AC-3 English audio, embedded subtitles, and a 6329.344-second duration.

## Automation gaps also corrected

- Added tested native Radarr/Sonarr Jellyfin update connections, including path mapping, so imports/renames/deletes trigger scans. Retained the five-minute fallback scan.
- Enabled Seerr's previously empty Movies/TV Shows library selection and verified status 5 (available).
- Enabled readable movie/episode names and sidecar subtitle import. Real rename propagated to Jellyfin/Bazarr, with the Hindi subtitle preserved.
- Set Seerr/browser links to HTTPS Caddy endpoints.
- Enabled qBittorrent category-based automatic management and bounded seeding; retained manager-controlled post-import removal.
- Added container health checks and deployed the Compose change through Portainer stack 153 without image upgrades.

## Validation and limits

Repeated 100 reads of a newly created hardlink while its original handle remained open; all passed. The test directory was removed. After downloader restart and category relocation, the real source/library inode and link count still matched.

Authenticated Jellyfin browser playback succeeded through Caddy, with Intel VA-API hardware decode, QSV H.264 encode, and AAC audio. Playback also succeeded after the Radarr rename, including a seek to 120 seconds. Browser `readyState=4`, error null, and zero dropped frames were observed. This validates a real playback session, not the entire feature-length file or every client/device.

All ARR service health checks and indexer/application/download-client tests passed. Bazarr detected English and Hindi with no missing subtitles. Sonarr's API connections and settings passed, but an actual TV episode acquisition/playback was not tested because the Shows library is empty. The mount fix survives configuration reload/remount; a whole-VM reboot was not performed during this incident.

## Future diagnosis

1. Check the latest Jellyfin FFmpeg log, not just Docker health.
2. Read/probe the exact library file inside the Jellyfin container.
3. If opening fails, compare with the download path and the local Store filesystem before blaming codecs or replacing the release.
4. Verify AV has `seal,nolease`; check a simultaneous download-handle/hardlink read.
5. After fixing file access, refresh failed probe metadata and test actual browser playback and seek.
6. Check Radarr/Sonarr Connect notifications and Seerr library selection if availability is delayed.
