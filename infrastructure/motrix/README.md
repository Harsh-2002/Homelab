# Motrix Server

Motrix runs as a Docker Compose project on `ctr` (`10.1.1.4`), with its source at `/data/apps/motrix/docker-compose.yml`. The official `motrixapp/motrix-server:2.0.0-beta.40` image has a private HTTPS UI at `https://downloads.l3b.cc.cd`; Caddy routes its Web UI/API to `10.1.1.4:8080` and `/mdxp` to `10.1.1.4:16801`. Both origin ports remain bound to the VM's LAN address, not every interface. Motrix advertises the HTTPS URL for pairing and no longer enables the direct-HTTP operator exception. There is no public Cloudflare DNS record for this hostname; outside the LAN, use Tailscale. The official Docker Hub repository has no `latest` or stable tag as of 2026-09-23, so this deliberately pins its current published beta instead of using a nonexistent tag.

`/data/apps/motrix/motrix-data` holds Motrix state and the generated operator token. It is on `ctr`'s local ext4 `/data` disk and owned by UID/GID 1000 (`ctr`). The external encrypted SMB share's `/mnt/AV/downloads` and `/mnt/AV/media` are bind-mounted as `/downloads` and `/media`. Both have 1000:1000 ownership. There is no separate `/mnt/media/downloads` on this VM. Do not recursively change permissions on the whole SMB share to deploy this stack.

Motrix defaults to `/downloads`, which Jellyfin does **not** index. In the Add Task folder picker, select `/media/movies` or `/media/shows` to save directly into a Jellyfin library, or enter the absolute path via Go to folder. The `/media` root is allowed and also contains `source`. Direct library downloads may appear in Jellyfin before transfer completion; use `/downloads` first and move completed files if you want to avoid that. The official server folder picker shows allowed roots in its Location sidebar; it does not browse the device running the browser.

The compose project is non-root, has a read-only root filesystem, a 64 MiB `/tmp` tmpfs, `no-new-privileges`, no privileged mode, and no Docker socket. The raw aria2 RPC listener remains on container loopback; only the Web and MDXP ports are published. The image supplies its own health check. Docker starts after `/data` and the `/mnt/AV` automount on this VM. Caddy applies its private-source policy but no Tinyauth gate because Motrix already requires an operator token and MDXP clients do not use browser login.

To recover from Git, copy this directory's `docker-compose.yml` and `.env.example` into `/data/apps/motrix`, naming the second file `.env`; verify its UID/GID against `/mnt/AV/downloads`. Create `motrix-data` owned by that UID/GID, confirm `findmnt -t cifs /mnt/AV` and `stat /mnt/AV/downloads`, then run `docker compose pull` and `docker compose up -d --wait` from `/data/apps/motrix`. The generated operator token is at `/data/apps/motrix/motrix-data/operator-token`; do not put it in Git or chat. Open the Web UI and paste the token into the unlock screen. The existing `Motrix` API Credential item in the HomeLab 1Password vault stores the current token; update that item if the server generates a replacement, rather than creating a duplicate.

Verify with `docker compose ps`, `docker logs motrix-server --tail 100`, `curl --resolve downloads.l3b.cc.cd:443:10.1.1.3 https://downloads.l3b.cc.cd/healthz`, and a small authorized test download. Deployment validation confirmed Docker health, an HTTPS 200 Web UI, actual create/delete operations inside `/media/movies` and `/media/shows`, and matching 401 responses to an unauthenticated MDXP POST through Caddy and directly. Startup logged both allowed roots (`/downloads`, `/media`); no transfer job was submitted. A healthy container alone does not prove a completed transfer.
