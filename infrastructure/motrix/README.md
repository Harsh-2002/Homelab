# Motrix Server

Motrix runs as a Docker Compose project on `ctr` (`10.1.1.4`), with its source at `/data/apps/motrix/docker-compose.yml`. The official `motrixapp/motrix-server:2.0.0-beta.40` image listens on `http://10.1.1.4:8080` for its Web UI and on `10.1.1.4:16801` for MDXP. Both ports are bound to the VM's LAN address, not every interface. There is no public DNS or Caddy route. The direct HTTP operator exception is appropriate only on the trusted LAN; use Tailscale or another encrypted path outside it. The official Docker Hub repository has no `latest` or stable tag as of 2026-09-23, so this deliberately pins its current published beta instead of using a nonexistent tag.

`/data/apps/motrix/motrix-data` holds Motrix state and the generated operator token. It is on `ctr`'s local ext4 `/data` disk and owned by UID/GID 1000 (`ctr`). The external encrypted SMB share's existing `/mnt/AV/downloads` is bind-mounted as `/downloads`; it already has the correct 1000:1000 ownership. There is no separate `/mnt/media/downloads` on this VM. Do not recursively change permissions on the whole SMB share to deploy this stack.

Motrix downloads are **not** automatically in Jellyfin. Jellyfin indexes `/mnt/AV/media/movies` and `/mnt/AV/media/shows`, not `/mnt/AV/downloads`. Move finished files to the appropriate media directory after checking their names and content, then let Jellyfin scan. The download root is the only share path visible to Motrix; it cannot write Jellyfin media directly.

The compose project is non-root, has a read-only root filesystem, a 64 MiB `/tmp` tmpfs, `no-new-privileges`, no privileged mode, and no Docker socket. The raw aria2 RPC listener remains on container loopback; only the Web and MDXP ports are published. The image supplies its own health check. Docker starts after `/data` and the `/mnt/AV` automount on this VM.

To recover from Git, copy this directory's `docker-compose.yml` and `.env.example` into `/data/apps/motrix`, naming the second file `.env`; verify its UID/GID against `/mnt/AV/downloads`. Create `motrix-data` owned by that UID/GID, confirm `findmnt -t cifs /mnt/AV` and `stat /mnt/AV/downloads`, then run `docker compose pull` and `docker compose up -d --wait` from `/data/apps/motrix`. The generated operator token is at `/data/apps/motrix/motrix-data/operator-token`; do not put it in Git or chat. Open the Web UI and paste the token into the unlock screen. The existing `Motrix` API Credential item in the HomeLab 1Password vault stores the current token; update that item if the server generates a replacement, rather than creating a duplicate.

Verify with `docker compose ps`, `docker logs motrix-server --tail 100`, `curl http://10.1.1.4:8080/healthz`, and a small authorized test download. Deployment validation confirmed Docker health, an HTTP 200 Web UI, and an actual create/delete operation inside `/downloads`; no transfer job was submitted. A healthy container alone does not prove a completed transfer.
